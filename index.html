A benchmark from chemometrics to tabular foundation models

Abstract

Model first, then the recipe for that model

Raman models now monitor bioreactors, identify bacteria and screen body fluids for disease, and each of them depends on a preprocessing choice made before training. Most evidence for that choice comes from studies of few datasets and few models, and tabular foundation models (TFMs) have rarely been tested on Raman spectra. In a large-scale benchmark, we apply 26 preprocessing recipes, fixed sequences of steps such as smoothing, baseline correction and normalization, to 15 models, from partial least squares (PLS) to TFMs, on 104 regression and classification tasks from 39 public datasets.

The choice of model changes the error more than the choice of recipe, and which recipe helps depends on the model. On unprocessed spectra a TFM is the best model for most regression tasks, and it stays ahead of the other models even when their recipe is chosen per task. Choosing the recipe per task by cross-validation (CV) within the training data lowers the error most, by a median of 16% against no preprocessing, and rarely makes a model much worse, also on small datasets. A recipe fixed per model family is a cheaper default that gains less, and descriptors of the dataset did not improve on it. Recipes with SNV or a scatter correction help most, whereas the second derivative often makes a model worse. Machine learning on Raman spectra therefore still benefits from preprocessing, but in regression a TFM needs none to outperform the other models, and the recipe can be chosen without inspecting the spectra. The 26 recipes are available in an open-source Python package with a scikit-learn interface, together with all code and the scores of every configuration.

Benchmark

Every recipe for every model, on 104 targets

Every model is fitted with each of the 26 recipes on every target of its task type, in 3-fold cross-validation. Regression is scored by RMSE and classification by balanced accuracy, always as the change against the unprocessed spectrum.

Choosing a recipe

Fixed per family, or chosen per task by CV

A recipe can be fixed for all models (global), fixed per model family or per model on other datasets, or chosen for each task by cross-validation inside its training folds. The oracle picks the best recipe on the test folds and only bounds what a choice could gain.

Use it

Four rules for a new Raman dataset

Choose the model first

It moves the error most: the model explains a median of 71% of the variance in regression RMSE, the recipe 9%.

In regression, start from the family recipe

snv for the chemometric models, all for the SVM at its default hyperparameters (sg_rubberband_snv when they are tuned), prep_ensemble for the tree ensembles and bc_snv_avgpool for the deep networks. For the TFMs no fixed recipe gains much; their family recipe, msc, lowers the error by about 5%.

Where the compute allows, choose per task by CV

Inside the training folds. In regression this roughly doubled the gain of SNV without seeing any test fold.

Check a fixed recipe against the unprocessed spectrum

The per-task choice already includes it; its failures became rarer with more data but did not disappear.

Every recipe is a scikit-learn transformer

A recipe runs the code the benchmark's models ran, so its output is exactly what they received.

# pip install "raman-bench>=1.6.0"
from raman_bench.preprocessing import recipe
from sklearn.cross_decomposition import PLSRegression
from sklearn.pipeline import make_pipeline

model = make_pipeline(recipe("snv"), PLSRegression(10, scale=False))
model.fit(X_train, y_train)   # one spectrum per row

Or let cross-validation choose

Try every recipe inside the training data; an exact tie goes to none.

from raman_bench.preprocessing import recipe, recipe_names
from sklearn.model_selection import GridSearchCV
from sklearn.pipeline import Pipeline

names = ["none"] + [n for n in recipe_names() if n != "none"]
search = GridSearchCV(
    Pipeline([("prep", recipe("none")), ("model", PLSRegression(10, scale=False))]),
    {"prep": [recipe(n) for n in names]}, cv=3,
    scoring="neg_root_mean_squared_error")
search.fit(X_train, y_train)
